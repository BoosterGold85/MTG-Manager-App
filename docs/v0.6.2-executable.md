BEGIN MTG MANAGER v0.6.2 — SYNERGY EXPLORER UX POLISH

Review the current main baseline first.

Treat v0.6.1 deck-aware Synergy scoring as approved and frozen from a scoring-model standpoint unless a real regression is found.

Do not redesign the scoring engine in this release.

Do not begin v0.7.0 New Set Watcher.

GOAL

Make Synergy Explorer easier to scan and understand on mobile without losing the detailed reasoning that already exists.

The current logic is useful, but candidate cards are too text-heavy in the default collapsed view.

The default candidate card should answer only:

- What is this card?
- How well does it fit?
- Do I own an available copy?
- Why is it a good or bad fit?
- Can I compare it?

Detailed engine math should be available on demand, not shown by default.

==================================================
1. SIMPLIFY CANDIDATE CARD DEFAULT VIEW
==================================================

Each candidate should default to a compact structure like:

Agate Instigator

Synergy 45 — Weak Fit

Available 1 · Owned 1

Weak fit: this deck already has enough payoff cards, and this does not strongly support the Dragon / Tokens plan.

[Why this score?]

[Compare Agate Instigator]

Do not show all score internals in the default card view.

==================================================
2. MOVE ENGINE LANGUAGE INTO DETAILS
==================================================

Move technical scoring language such as:

- Payoffs 23/10
- contextual target
- component totals
- exact role-count math
- penalty arithmetic
- raw score
- clamped score
- package counts

into a collapsed section:

WHY THIS SCORE?

The default user-facing explanation should translate that logic into normal language.

Example:

CURRENT:
“Payoffs 23/10 already exceeds the contextual target.”

DEFAULT UI:
“This deck already has plenty of payoff cards.”

DETAIL VIEW:
“Role need: Payoffs 23 / target 10
Role contribution: 0
Redundancy penalty: -X”

Preserve the exact underlying score breakdown.

Do not remove diagnostic information.

==================================================
3. HUMAN-READABLE REASON GENERATION
==================================================

Create deterministic summary copy for each candidate.

Preferred format:

Strong fit:
“Supports Dragons and Tokens, fills a needed ramp role, and directly reinforces the Commander.”

Worth considering:
“Fits the Dragon plan and provides useful interaction, but the deck already has several cards serving this role.”

Weak fit:
“Provides some useful support, but does not strongly reinforce the deck’s primary strategy.”

Not recommended:
“Does not meaningfully support the primary Dragon / Tokens plan and does not fill an important missing role.”

Keep summaries concise:
1–2 sentences maximum.

Do not use an LLM.

Do not invent reasons not supported by the scoring evidence.

==================================================
4. RECOMMENDATION TIERS
==================================================

Preserve the existing scoring bands:

Recommended
70+

Worth Considering
50–69

Other Legal Cards
Below 50

Other Legal Cards should remain collapsed by default.

Recommended and Worth Considering should visually receive the most attention.

Do not make low-scoring legal cards look equally important.

==================================================
5. REDUCE MOBILE VERTICAL DENSITY
==================================================

Optimize candidate cards for mobile.

Reduce unnecessary vertical spacing between:

- score
- ownership
- summary
- actions

Avoid giant text blocks in the default view.

Keep artwork large enough to recognize.

Candidate cards should be quickly scannable with one-handed scrolling.

Do not shrink text below the approved mobile readability rules.

==================================================
6. WHY THIS SCORE?
==================================================

Replace or rename the current technical “Score breakdown” affordance to:

Why this score?

Inside the expanded section show:

- Commander fit
- Primary strategy fit
- Needed role
- Packages
- Contextual efficiency
- Generic overlap
- Curve fit
- Negative adjustments
- raw score
- final score

Where useful, show both plain-English reasoning and exact values.

Example:

Needed role
This deck already has enough payoff effects.
Payoffs: 23 / target 10
Contribution: 0

Negative adjustment
Redundant payoff role: -8

Keep this collapsed by default.

==================================================
7. RECOMMENDATION CARD HIERARCHY
==================================================

Default visual hierarchy should be:

1. Card artwork
2. Card name
3. Synergy score + tier
4. Availability
5. One-sentence reason
6. Why this score?
7. Compare

Do not place secondary engine diagnostics above the comparison button.

==================================================
8. OWNERSHIP DISPLAY
==================================================

Keep ownership concise.

Preferred:

Available 1 · Owned 1

If fully assigned:

Owned 2 · Available 0
Used in: Deck A, Deck B

Do not let ownership data dominate strategic reasoning.

==================================================
9. COMPARISON FLOW
==================================================

Preserve existing Compare behavior.

The candidate card should still provide:

Compare [Card Name]

When comparing candidate vs deck card, keep the full detailed scoring evidence available.

Do not auto-swap cards.

Do not auto-remove cards.

Do not label a comparison result as definitively “better” unless the UI clearly says the result is based on the local Synergy heuristic.

==================================================
10. LOW-SCORE CARDS
==================================================

Other Legal Cards should remain collapsed.

When expanded, low-score cards should use subdued styling.

Use labels such as:

Weak Fit

Poor Fit

Not Recommended

Avoid alarming language.

These cards are still legal and may have niche uses.

==================================================
11. SEARCH / FILTER BEHAVIOR
==================================================

Preserve:

- candidate search
- availability filtering
- tier grouping
- progressive rendering
- score-first ranking
- tie-breaking behavior

Do not change scoring order.

Do not reintroduce availability-first ranking.

==================================================
12. PERFORMANCE
==================================================

Do not recompute Synergy merely because a section expands or collapses.

Use existing cached profile and score data.

Why this score? should render from existing score evidence.

Scrolling through candidates should remain smooth on mobile.

==================================================
13. REAL-WORLD ACCEPTANCE TEST
==================================================

Use the Lathliss Dragon deck fixture and verify the first visible recommendations make intuitive sense.

Confirm:

- strong Dragon cards remain high
- off-plan creatures remain low
- role redundancy explanations read naturally
- low cards are not presented as recommendations
- no recommendation changes merely because UI wording changed

The purpose of this release is presentation clarity, not scoring changes.
