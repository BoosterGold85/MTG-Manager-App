STEP 2 OF 2 — MTG MANAGER v0.5.0: DECK DNA CORE

Review the current main baseline first.

Treat v0.4.2 Deck Browsing & Card Navigation as approved and frozen.

Preserve:
- Collection behavior
- ManaBox collection import
- ManaBox deck import
- Commander Library
- physical-copy assignments
- deck persistence
- deck sorting/navigation
- shared Card Detail
- Card Intelligence
- Keywords
- Oracle search
- visual identity
- backup behavior

Do not redesign approved systems.

Do not begin v0.6.0.

GOAL

Make MTG Manager understand and explain what a Commander deck is trying to do.

This release should answer:

- What does this deck do?
- What are its strongest themes?
- How does the Commander influence those themes?
- Which cards are most central to the strategy?
- Why does a specific card fit this deck?

The system must remain:
- local
- deterministic
- explainable
- based on existing Card Intelligence
- independent of paid LLM/API services

==================================================
1. DECK DNA
==================================================

Add a prominent Deck DNA section to each Commander deck page.

Analyze the entire conceptual decklist using existing:

- strategic tags
- tag categories
- Keywords
- card types
- creature subtypes
- mana values
- Commander signals
- payoff/enabler relationships
- Card Intelligence evidence

Identify approximately the top 4–7 meaningful themes defining the deck.

Example:

DECK DNA

Dragons Matter      38%
Tokens              21%
Go Wide             15%
Ramp                 11%
Combat                9%
Card Advantage        6%

These percentages are descriptive theme weights.

They are NOT:
- probabilities
- power levels
- card-quality ratings
- simple percentages of cards containing a tag

Normalize the displayed primary themes to approximately 100%.

Avoid allowing minor incidental mechanics to become major Deck DNA themes.

==================================================
2. COMMANDER INFLUENCE
==================================================

The Commander should influence Deck DNA more strongly than a normal deck card.

Strong Commander evidence includes:

- directly references a theme
- explicitly rewards a mechanic or creature type
- acts as a payoff
- acts as an enabler
- repeatedly connects to a strategy seen throughout the 99

Example:

A Dragon creature should provide some evidence toward Dragons.

A Commander saying:

“Whenever you cast a Dragon...”

should provide much stronger evidence.

Do not let the Commander completely dictate the analysis.

If the actual 99 are built around a different strategy, the actual decklist should still control the final DNA.

==================================================
3. THEME WEIGHTING
==================================================

Build the scoring system as an explicit reusable engine.

Conceptual weighting:

STRONG
- Commander directly references theme
- explicit payoff
- explicit “X Matters”
- repeated strategy across many cards

MEDIUM
- enabler
- supporting mechanic
- resource generation
- repeatable support

WEAK
- incidental compatibility
- merely possessing a card type or characteristic

Preserve the semantic lessons from v0.3.2.

Examples:

Being an artifact does not automatically mean Artifacts Matter.

Having a +1/+1 counter does not automatically make a card central to a counters deck.

Creating one Treasure does not automatically make Treasure a dominant deck theme.

==================================================
4. THEME FAMILIES
==================================================

Prevent redundant DNA results from overwhelming the display.

Introduce higher-level theme families for presentation.

Examples:

GRAVEYARD
- Reanimator
- Recursion
- Self-Mill
- Graveyard Payoff

COUNTERS
- +1/+1 Counters
- Counter Payoff
- Proliferate

TOKENS
- Tokens
- Token Payoff
- Go Wide
- Populate

Deck DNA may display the broad family while allowing the user to inspect contributing subthemes.

Do not delete or rewrite the underlying Card Intelligence taxonomy.

Theme families are an aggregation/presentation layer above existing tags.

==================================================
5. WHAT THIS DECK DOES
==================================================

Add a concise section directly below Deck DNA:

WHAT THIS DECK DOES

Generate a deterministic 1–2 sentence summary from the strongest Deck DNA signals.

Example:

“Cast Dragons, generate additional Dragon tokens through Lathliss, and build a large flying board that closes games through combat.”

Reference the Commander when the Commander materially drives the strategy.

Do not use generic filler prose.

Do not invent a strategy when evidence is weak.

Use deterministic templates/composition rather than an LLM.

==================================================
6. CORE PLAN
==================================================

Add a compact Core Plan section.

Example:

Primary strategy
Dragons / Combat

Supporting engines
Tokens · Ramp

Primary payoff
Wide Dragon board

Do not provide speculative turn-by-turn play instructions.

Do not claim a win condition unless actual deck evidence supports it.

==================================================
7. CARD SYNERGY SCORE
==================================================

Assign every non-Commander deck card a deck-relative Synergy score from 0–100.

The score answers:

“How strongly does this card support this specific deck?”

Consider:

- overlap with dominant Deck DNA themes
- interaction with Commander themes
- payoff/enabler relationships
- creature-type synergy
- strategic tags
- relevant Keywords/mechanics
- supporting roles

Do NOT include:

- card price
- EDHREC popularity
- external rankings
- generic card power
- market value

A cheap card may have higher synergy than an expensive staple.

Synergy first, raw power second.

Do not present the score as mathematically precise.

A score of 92 vs 90 should effectively mean both cards are highly synergistic.

==================================================
8. EXPLAIN SYNERGY
==================================================

The Synergy score must be inspectable.

Example:

SYNERGY 91

Strong connections
- Dragons Matter
- Tokens

Commander connection
- Lathliss rewards casting Dragons

Supporting role
- Payoff
- Token Generator

Never show unexplained magic numbers.

==================================================
9. IN THIS DECK
==================================================

Extend the shared Card Detail component from v0.4.2.

When Card Detail is opened from a deck, add a contextual section:

IN THIS DECK

Show:

- Synergy score
- strongest Deck DNA connections
- Commander connection
- primary deck role
- supporting deck roles where useful

Keep the distinction clear:

CARD INTELLIGENCE
= What this card generally does

IN THIS DECK
= Why this card fits this specific deck

Do not mix deck-relative analysis into universal Card Intelligence.

==================================================
10. SYNERGY SORTING
==================================================

Extend the existing deck Sort control from v0.4.2.

Add:

Synergy
- High → Low
- Low → High

Existing Previous/Next Card Detail navigation must respect Synergy sorting.

Example workflow:

Sort:
Synergy Low → High

Open weakest card.

Inspect:
- Oracle text
- Card Intelligence
- In This Deck
- synergy reasoning

Tap Next.

Continue through the weakest cards without leaving Card Detail.

==================================================
11. DECK DNA THEME FILTER
==================================================

Add lightweight Deck DNA filtering.

Allow the user to select a displayed Deck DNA theme and show only cards contributing to that theme.

Examples:

Theme: Dragons

Theme: Ramp

Theme: Graveyard

This should work with the existing deck sort system.

Previous/Next navigation must follow the currently filtered + sorted sequence.

Do not build a huge new filter system.

==================================================
12. CARD TILE SYNERGY DISPLAY
==================================================

When the deck is sorted by Synergy, display the Synergy score as the primary secondary metric on each card tile.

Example:

SYNERGY 91

Do not permanently add the score to every card tile in every mode.

Preserve the v0.4.2 principle:

the active sort/view determines which secondary metric deserves emphasis.

==================================================
13. BASIC COMPOSITION
==================================================

Preserve the existing Basic Composition section.

Do not make generic stats more visually important than Deck DNA.

Optional additions are acceptable if low-risk:

- average mana value
- simple mana curve

Do not turn the deck page into a stats dashboard.

==================================================
14. DECK PAGE HIERARCHY
==================================================

Use approximately this hierarchy:

1. Deck identity
   - deck name
   - Commander
   - color identity
   - ownership status

2. Deck DNA

3. What This Deck Does

4. Core Plan

5. Basic Composition

6. Deck cards
   - sorting
   - theme filtering
   - existing card navigation

Keep progressive disclosure.

Do not make the top of the page excessively tall on mobile.

==================================================
15. MISSING CARDS
==================================================

Conceptual decklist cards that are not currently owned must still participate in Deck DNA.

Ownership status must not distort strategy analysis.

Keep separate:

Decklist identity

from:

Physical ownership assignment

A missing card can still strongly contribute to the deck’s strategy.

==================================================
16. RECALCULATION LIFECYCLE
==================================================

Recalculate Deck DNA when:

- card added
- card removed
- Commander changes
- ManaBox deck import changes deck entries
- relevant Card Intelligence ruleset changes

Do NOT recalculate on every render.

Cache derived analysis using:

- stable deck revision
- Card Intelligence ruleset version

Deck DNA is derived data.

It must always be safe to rebuild.

==================================================
17. PERFORMANCE
==================================================

A normal 100-card Commander deck should analyze quickly on modern mobile hardware.

Reuse canonical Card Intelligence results.

Do not rerun Card Intelligence separately for each printing of the same canonical card.

Analyze canonical card identity once and aggregate deck signals.

Opening an unchanged analyzed deck should feel immediate.

Previous/Next navigation must not trigger Deck DNA recalculation.
